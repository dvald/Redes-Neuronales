TEMA 9 · IBig Data: aceleración con GPU

Por qué la GPU entrena las redes mucho más deprisa que la CPU, qué software la hace utilizable y cómo conseguir que no se quede esperando datos ni sin memoria.

Big Data: el desafío de las 4V

Animación ilustrativa

Las aproximaciones tradicionales se quedan pequeñas: hay muchísimos datos, de orígenes muy distintos, que llegan sin parar y no siempre son fiables.

Tres tipos de datos

La variedad de formatos exige arquitecturas neuronales más flexibles y complejas.

  • Estructurados: filas y columnas con un significado fijo (bases de datos relacionales).
  • Semiestructurados: llevan etiquetas o claves, pero cada registro puede tener una forma distinta.
  • No estructurados: píxeles, muestras de sonido o palabras sin esquema; la red tiene que descubrir por sí misma las características.
Idea clave: el deep learning trabaja sobre todo con datos no estructurados y en volúmenes enormes. Por eso necesita hardware especializado.

Problemas actuales

  • Las redes son cada vez más complejas y grandes.
  • Necesitan grandes volúmenes de datos para aprender.
  • El tiempo de entrenamiento crece muy deprisa.
  • Los ordenadores domésticos (CPU) resultan insuficientes.
ModeloAñoParámetrosSolo los pesos (FP32)

Cada parámetro en 32 bits ocupa 4 bytes. Entrenar necesita bastante más memoria: gradientes, estado del optimizador y activaciones (pestaña 7).

Idea clave: más parámetros y más datos multiplican las operaciones. Con una CPU el entrenamiento se eterniza: hace falta hardware que calcule en paralelo, la GPU, que reduce los tiempos de semanas a horas.

Pocos núcleos potentes frente a miles de núcleos sencillos

Simulación simplificada

La misma cola de tareas en los dos chips. Cada núcleo de la CPU termina antes su tarea, pero la GPU termina muchas más a la vez.

Tipo de trabajo
Latencia de una tareaCaudal máximoTiempo total
  • Con tareas independientes (como las celdas de una matriz) la GPU arrasa: trabaja en todas a la vez.
  • Con tareas encadenadas (lógica «if-else», cada paso necesita el anterior) solo puede trabajar un núcleo, y la CPU, más rápida por núcleo, gana.

Velocidades supuestas para ilustrar la idea (u.t. = unidades de tiempo). Una CPU de escritorio tiene del orden de 4 a 32 núcleos; una GPU actual, miles.

Idea clave: la CPU minimiza la latencia (cada tarea acaba pronto); la GPU maximiza el caudal (throughput: tareas terminadas por unidad de tiempo). Entrenar una red es, sobre todo, trabajo paralelo.

CPU y GPU no compiten: colaboran

La GPU no funciona sola: necesita un host, la CPU, que le envíe instrucciones y datos a su memoria.

✓ Ventajas de la GPU
  • Paralelismo masivo: miles de operaciones simultáneas.
  • Rendimiento numérico superior en cálculo matricial.
  • Eficiencia energética: mejor rendimiento por vatio en cargas paralelas.
  • Escalabilidad para Big Data.
✗ Inconvenientes
  • Tareas secuenciales: rinde mal con lógica compleja «if-else».
  • Complejidad: requiere programación específica (CUDA).
  • Memoria limitada: la VRAM es fija, un problema con modelos gigantes.

Cada celda es una fila por una columna

Cálculo real en el navegador

Para obtener C = A × B se multiplica una fila de A por una columna de B, elemento a elemento, y se suma. Pasa el ratón por una celda de C.

Idea clave: no hace falta conocer C[0][0] para calcular C[0][1]. Cada celda es independiente de las demás, así que se pueden calcular todas a la vez. Ahí está la ventaja de la GPU.

La pila de software: de Keras a los núcleos

Animación ilustrativa

Tu código no habla directamente con la GPU: cada capa traduce la petición para la capa de abajo.

CUDA (NVIDIA, 2006)

Permitió usar la GPU para cálculo general, no solo gráficos. Es una extensión del lenguaje C con una API propia que divide las tareas en bloques de hilos.

cuDNN

Librería sobre CUDA para deep learning: convoluciones, activaciones y retropropagación muy optimizadas. Una «caja negra» eficiente que TensorFlow y PyTorch usan por dentro.

Un kernel: una malla de bloques de hilos

Animación ilustrativa

Un kernel es la función que ejecuta cada hilo. Para C = A × B de 32 × 32, cada uno de los 1024 hilos calcula una celda. Pasa el ratón por una celda.


          

          
Los hilos de un bloque se ejecutan en grupos de 32 (warps): un bloque de 8 × 8 = 64 hilos son 2 warps. Los bloques se reparten entre los multiprocesadores (SM) de la GPU.

Precisión mixta: 16 bits donde basta

      
Cálculo real (redondeo IEEE 754)

      
Las GPU modernas (RTX) tienen Tensor Cores para cálculos en 16 bits. Un número en FP16 ocupa la mitad y pierde algo de precisión.

      

        
Ejemplos
          

        

        

      

      


# En Keras / TensorFlow
from tensorflow.keras import mixed_precision
mixed_precision.set_global_policy('mixed_float16')

      
    
        
  • Con la política mixed_float16, las operaciones y las activaciones van en 16 bits y los pesos se guardan en 32: se gana velocidad y memoria sin perder precisión notable.
    • 
        
  • FP16 tiene poco rango: por encima de 65.504 se desborda y los números muy pequeños (como algunos gradientes) se vuelven 0. Por eso, con esta política, Keras escala la pérdida automáticamente.
    • 
      

      
Idea clave: si tienes una GPU RTX, activa mixed_float16: reduce el uso de VRAM a la mitad y puede duplicar la velocidad.
